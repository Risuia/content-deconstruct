# 合规边界

拆解是研究行为，不是采集行为。这条区分决定了哪些路能走、哪些路不能走。

## 采集优先级

从高到低，能用上面的就不要用下面的：

1. **官方开放平台** —— 有授权、有配额、有明确条款
2. **平台官方工具** —— 平台自己提供的导出或分享能力
3. **第三方合规 API** —— 有商业授权与数据来源说明的服务
4. **浏览器插件** —— 复用用户自己已登录的会话，低频、人工触发
5. **自建爬虫** —— 仅公开页、严格限速、只读
6. **协议逆向 / RPA** —— 高风险，本项目不做

## 几条不做的事

**不绕过登录态与风控。** 小红书的签名头、设备指纹属于风控体系，逆向它属于规避技术保护措施。抖音的 `a_bogus` 同理——正确做法是用浏览器插件复用已登录会话，而不是破解签名算法。

**不采未授权个人数据。** 只碰公开发布的内容与其公开互动数据。不采集私信、非公开粉丝列表、手机号等任何个人信息。

**不建持久镜像库。** 证据包跟着作品走，一次一包，不做增量同步、不做长期归档、不对外提供检索。这一条同时也是质量要求——证据包如果不绑定到具体作品，引用就会串稿。

**不产出可照抄的成品。** 拆出来的是结构与配方，不是文案。仿写必须换题材、换表达、换素材。直接把拆解结论套上原内容，就是搬运。

## 频率

遵守各平台官方节奏。小红书官方 API 默认 QPS=1，不要并发压测。B站接口短时间内重复裸请求会触发 -352，这既是技术限制也是频率信号。

## 数据使用的自我约束

- 拆解产出仅用于自己分析，不传播、不售卖、不二次分发原始数据
- 报告中引用原文时标注来源（BV 号 / 作品链接 + 时间戳），保留可追溯性
- 涉及的第三方创作者信息只保留公开可见部分

## 一个判断标准

如果某条路径的可行性依赖于「平台没发现」，那它不能用于日常流程。可以偶尔手动验证一次，但不能写进工作流——写进去之后，整条链路的稳定性就交给平台的封堵节奏了。
