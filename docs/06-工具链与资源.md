# 工具链与资源

这一份讲执行层：用什么工具、装多少东西、消耗多少资源。方法论在 [`02-执行流程.md`](02-执行流程.md)，这里只讲落地。

## 依赖分级

拆解不需要重型环境。按需装，不要一次装完。

| 能力 | 依赖 | 重量 | 是否必需 |
|---|---|---|---|
| B站采集 / 候选推荐 / cid 补全 | 纯标准库 | 0 | 必需，无需安装 |
| 抖音游客态采集 | websocket-client | 几 MB | 按需 |
| 视频下载 | yt-dlp | 几十 MB | 按需 |
| 抽帧 | ffmpeg 或 imageio-ffmpeg | 约 80 MB | 按需 |
| 音频转写 | whisper / FunASR | **GB 级** | 按需，单独建环境 |

**原则**：先只用标准库把证据拿全，确认这条内容值得深挖，再装转写。多数拆解在第 4 步之前就能得出结论。

## 本地工具链入口

如果脚本散成了几十个，用一个统一入口包起来，让 AI 走「发现 → 查契约 → 检查环境 → 执行」四步，而不是读源码猜参数。

| 命令 | 作用 |
|---|---|
| `kit.py list` | 列出全部能力与状态（JSON） |
| `kit.py describe <id>` | 单一能力的完整契约与底层命令 |
| `kit.py check` | 本机资源与可用性 |
| `kit.py run <id> --args` | 执行 |

输出契约：`run` 的 stdout 恒为单个 JSON 对象，人类可读进度走 stderr。字段包含 `status`、`exit_code`、`result`、`artifacts`、`stdout_tail`、`stderr_tail`。

**证据引用必须带定位信息**：引用转写原文时，附上 `platform | work_id | span | seg | transcript_sha | speaker`，这是防串稿和防无据引用的硬约束。

## 退出码语义

| 码 | 含义 | 该怎么做 |
|---|---|---|
| 0 | 成功 / dry_run | 用 `result` 或 `artifacts` 继续 |
| 2 | 参数或能力不存在 | 先 `describe`，不要重试瞎猜参数 |
| 3 | 已排除 | 走替代路径，**不要尝试绕过** |
| 4 | 被阻塞 | 看 `require` 字段；网络 / 登录需显式授权，或改用离线数据 |
| 5 | 底层脚本失败 | 看 `subprocess_returncode` / `stderr_tail`，不得把 stdout 当正文 |

## 转写参数

长音频必须加抗幻觉参数，否则会出现整段重复：

```
-mc 0      不继承上文上下文（重复幻觉主因）
-et 2.4    提高熵阈值，抑制低置信度乱码
-lpt -0.5  降低对数概率阈值，减少无中生有
-nf        关闭温度回退
```

模型路由建议：`small` 用于初稿与定位，`medium` 以上用于需要引用的段落。语速快、术语多的内容才值得上大模型，普通口播用 small 更快。

## 资源消耗的几个误区

**模型文件大小 ≠ 峰值内存。** 看到 3 GB 的模型不要假设要 3 GB 内存，实际峰值由解码策略和并发决定，要用一次小样本实测，不要按文件体积推算。

**公开的加速数字必须带硬件和模型。** 「快 10 倍」这类说法离开了具体芯片和具体模型就没有意义，不要拿别人的数字做自己的容量规划。

**口播不需要上传整份高清录屏。** 只取音轨就够，几十 MB 的音频和几 GB 的视频对转写没有区别。

**校对时间可能比云端账单更贵。** 换更大的模型不如把时间花在校对上一版底稿，尤其是只有少数术语出错的时候。

**API 消耗来自实际上下文和重复调用。** 同一份证据包不要反复整包送入，做成分段索引、按需检索。

## 需要 Key 的路径

| 方案 | 覆盖 | 说明 |
|---|---|---|
| Just One API | B站 + 抖音 + 小红书 | 一个 Token 覆盖三平台，B站接口直接给弹幕与字幕 |
| Rnote API | 小红书 | `/api/v2/crawler` 公开内容 + `/api/v2/pgy` 蒲公英投放数据 |
| SandBase 类 | 抖音 + 小红书 + 微博 | 统一 `POST /v1/api/{platform}/app-v2/{endpoint}` |
| 抖音开放平台 | 抖音（仅授权账号） | 需企业资质，纯采集过不了审 |
| 小红书开放平台 | 小红书（偏电商） | 笔记发布无公开 API；阅读量属蒲公英数据面 |

**小红书数据边界**：阅读量不在公开消费端，须走蒲公英，且部分帖子指标可能不可用，需要做空值兜底。
