# 输出格式

格式不是排版问题，是约束问题。固定的骨架强制每一条结论都必须落到证据上，写不出证据的位置会立刻暴露成空白。

## 完整骨架

```
■ 钩子（前 3 秒）
  画面：       首帧里最抢眼的是什么
  口播：       第一句话说了什么
  屏幕文字：   有没有花字，写了什么
  音频：       音乐 / 音效 / 静音
  生效时间点： 第几秒观众开始反应
  留人机制：   悬念 / 冲突 / 反常识 / 视觉冲击 / 其他

■ 结构骨架
  时间区间 | 章节 / 内容 | 画面策略 | 弹幕密度 | 观众情绪

■ 情绪曲线
  时间点 | 情绪 | 强度 | 触发原因

■ 争议点
  评论区高赞质疑 + 对应弹幕时间

■ 传播基因
  靠什么传播：梗 / 选题 / 形式 / 情绪

■ 可复用配方
  公式：      一句话概括这条内容的结构公式
  必须保留：  去掉就不成立的部分
  必须避开：  这条内容踩了、但没必要跟着踩的部分
  适用时长：  这个公式在哪个体量下成立

■ 置信度
  高 / 中 / 低 + 缺失的证据说明
```

## 每部分的写作要求

**■ 钩子** —— 只写前 3 秒，不要扩展到前 10 秒。每一项都要有观察来源：画面来自首帧，口播来自转写首句，屏幕文字来自读图，生效时间点来自弹幕。

**■ 结构骨架** —— 必须是表格，必须有弹幕密度列。没有密度列的结构表只是内容摘要，任何人读完原文都能写，不需要拆解。

**■ 情绪曲线** —— 只记录转折点，不记录全过程。四到六个点足够，多了说明没有做归纳。

**■ 争议点** —— 高赞质疑要带点赞数，对应弹幕要带秒数。两者缺一，就只是「有人不喜欢」这种废话。

**■ 传播基因** —— 四选一或四选二，不要四条都写。全都占的内容不存在，四条都写说明没判断。

**■ 可复用配方** —— 这是唯一允许抽象的部分，但抽象必须建立在前五部分之上。「必须避开」最容易被省略，而它往往是最有价值的一条。

**■ 置信度** —— 按 [README](../README.md#置信度规则) 中的置信度表判定，并明确写出缺了哪些证据、因此不能得出什么结论。

## 反例

以下写法一律判定为失败：

- 「结构清晰，节奏紧凑，情绪饱满」—— 换成任何一条内容都成立
- 「前 3 秒用悬念吸引观众」—— 没有说悬念具体是什么
- 「评论区反响热烈」—— 没有点赞数，没有具体观点
- 「这条视频的成功在于选题好」—— 选题好是结论不是原因
- 任何以「可能」「通常」「一般来说」开头的判断句

## 与其他格式的关系

单作品拆解的完整报告骨架（含证据层 / 结构层 / 解释层三层分离、七个章节、附录与自动验收断言）见 [`templates/单作品拆解模板.md`](../templates/单作品拆解模板.md)。

本文件是**结论层**的格式，那份模板是**交付层**的格式：先用本文件的骨架得出结论，再按模板组装成可交付的报告。
