# 失败模式

按发生位置分成三层：采集层（请求拿不到数据）、判定层（拿到数据但结论错）、工具层（流程跑完但产物不可信）。

## 采集层

**B站裸请求返回 `{"code":-352}`。** 必须带完整 UA 和 `Referer: https://www.bilibili.com/`。这也解释了为什么 WebFetch 能通而 curl 裸请求会失败——WebFetch 自带完整浏览器头。

**oid 用错类型。** 弹幕用 `cid`，评论用 `aid`。填反了静默返回空，不报错，是所有失败里最难排查的一个。

**`ps` 参数上限 20。** `x/v2/reply` 传 `ps=25` 报 `-400 ps out of bounds`。

**`weekly/list` 已下线。** 返回 404，改用 `ranking/v2`。

**UP 主投稿列表触发 -352。** 改用 `popular` + `ranking` + 搜索页 HTML 绕过。

**字幕是登录态接口。** `need_login_subtitle:true` 时不要反复请求，改用「分章 + 弹幕 + 封面图 + 评论」组合替代。

**判断成功要看四件事**：HTTP 200 + body 长度 > 0 + 目标字段非 null + 业务 `code` 为 0。四者同时满足才算拿到数据。

### 抖音的「假成功」

`www.douyin.com/aweme/v1/web/hot/search/list/` 返回 HTTP 200 但 body 0 字节；App 端搜索 `status_code:0` 但 `aweme_list` 为 null。

**200 不等于有数据。** 抖音热点榜要用 `snssdk` 域，不要用 www 域。

### 小红书的两个陷阱

**假 noteId。** `__INITIAL_STATE__` 里 22 个 24 位 hex ID 来自 `disableLikeNotes` 灰度名单，不是真实笔记。拿到 ID 必须先验证能否打开。

**note_url 不能重建。** `xsec_token` 等 query 参数必须原样保留，用 note_id 拼出来的链接读不到内容。

**curl 与 WebFetch 行为不同。** 小红书 explore 页 curl 会 302 跳登录，但 WebFetch 能读到标题列表；详情页两者都读不到。同一 URL 换工具结果不同，不要据此判断「接口失效」。

## 判定层

判定层的错误比采集层严重，因为数据都拿到了，结论却是错的。

**把复述当拆解。** 输出全是「这条视频讲了什么」，说明只做了摘要。检验方法：把结论里的具体内容替换成另一条视频的内容，如果句子照样通顺，那它就不是这条视频的拆解。

**用绝对播放量选内容。** 必须用效率指标。大号的绝对量天然高，选出来的是大号而不是好内容。

**用热门榜快照做趋势。** 热门榜 stat 是入榜时刻的快照。做效率排序没问题；做绝对量对比或趋势必须用 `view/detail` 取实时值——同一条视频一周内可以从 217 万涨到 1061 万。

**把采集量当平台总量。** 弹幕和评论的采集量 ≠ 平台总量（含已删除、折叠、风控截断）。任何比例计算前先确认分母。

**新发布就下结论。** 24 小时内互动稀疏，弹幕曲线未成形，任何结构判断都要显式标注「数据稀疏」。

**用「可能 / 通常 / 一般来说」填空白。** 这三类词是缺证据的遮羞布。拿不到就说拿不到。

## 工具层

流程跑通不等于产物可信，以下几条来自 2026-11-13 的转写工具链复核。

**转写后端 `exit != 0` 时，stdout 只是错误横幅。** 不得把 stdout 当正文。

**`exit = 0` 但产物缺失时，同样不得用 stdout 兜底。**

**长音频重复幻觉。** 转写必须加抗幻觉参数，实测必须：

```
-mc 0      不继承上文上下文（长音频重复幻觉主因）
-et 2.4    提高熵阈值，抑制低置信度乱码
-lpt -0.5  降低对数概率阈值，减少无中生有
-nf        关闭温度回退
```

**ASR 底稿不是原话。** 未回听校订的转写不得当作作者原话引用，错词要标 `[听辨待核≈猜测]`。

**yt-dlp 文件名规则。** `-o "dl.%(ext)s"` 得到 `dl.mp4`，ffmpeg 输入路径要跟实际文件名对上，否则抽帧会静默失败。

**固定间隔抽帧。** 纯图 / PPT 式视频用 `select='gt(scene,0.3)'` 做场景检测，固定间隔会抽出几十张重复帧。
