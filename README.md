# 内容拆解（Content Deconstruct）

**把一条内容还原成带时间戳的证据包，再在统一时间轴上做归因。**

拆解 B站、抖音、小红书创作内容的纯 AI 工作流：不写爬虫、不接开放平台授权、不存向量库、不建 Schema 表，只输出可复用的创作配方与传播基因。

## 一、结论

大多数所谓拆解，损耗不在「模型不够强」，而在流程：

**输入没有先确认有效片段；口播内容却用整屏逐秒 OCR；底稿没有可回听的校对；证据与结论之间没有绑定；算得出来的指标被当成有意义的结论。**

所以这套工作流的重心不是换模型，是把四件事做实：**先拿到带时间信号的真实证据、在时间轴上对齐、每条结论绑定证据、说清缺了什么。**

方向是：以 B站弹幕与官方分章为主轴做归因，抖音只做选题预判，小红书按需引入 Key；新工具只在小样本上比较，不一次装齐。

## 二、先立口径

这套工作流的所有判断都依赖两条口径，单独成篇：[`docs/00-证据口径与状态契约.md`](docs/00-证据口径与状态契约.md)。

**状态四态**：已部署 ≠ 能启动 ≠ 实跑通过 ≠ 质量验收。越级判断是这类工作最贵的错误——模型文件在，不代表转写可用；输出文件落盘，更不代表流程闭环（失败前也会落盘）。

**证据四级**：本机实测 / 官方声明 / 分析者建议 / 仍待验证。官方说支持，不等于本机能跑通；厂商基准不等于本机基准。

本仓库据此只对自身声明到「已交付文档」一层，**不声明任何一条采集链路当前可用**——平台接口会变，可用性必须每次实测。

## 三、缺口与代价

按「环节 → 问题 → 代价 → 优先级」列。P0 的含义是：不做，后面所有结论都不可信。

| 环节 | 已观察到的问题 | 代价 | 优先级 |
|---|---|---|---|
| 证据完整性 | 只有评论、没有弹幕时仍输出「结构分析」 | 无时间信号的结构是编的 | P0 |
| 采集口径 | 采集量被当成平台总量 | 比例算错，观众判断失真 | P0 |
| 原文可靠性 | 自动转写未校订，却当作者原话引用 | 论证建在错字上 | P0 |
| 画面证据 | 没抽帧读图，就断言镜头与配乐 | 生成不存在的观察 | P0 |
| 平台覆盖 | 小红书免登录不存在，第三极实际缺位 | 「三平台」说法名不副实 | P0 |
| 字幕获取 | `ai-zh` 需登录态，反复请求触发风控 | 口播原文只能靠转写 | P1 |
| 结论可回查 | 报告写了结论，但指不回具体秒数 | 无法复核，也无法复用 | P1 |
| 指标解释 | 命中率算得出来，但没扣偶然基线 | 精确数字掩盖错误解释 | P1 |
| 重复消耗 | 同一作品的不同录屏被当成两条 | 重复分析、账号混淆 | P2 |
| 评论数据 | 抓到条数 ≠ 全量 | 从非代表性样本推观众 | P2 |

## 四、三平台能力边界

2026-10-29 本机实测。三个平台不是对等的三条路，是互补的分工。

| 数据面 | B站 | 抖音 | 小红书 |
|---|---|---|---|
| 实时榜单 | ✅ 热门流 + 排行榜 + 热搜 | ✅ App 端热点榜（免签名） | ❌ 需 Key |
| 单条详情 | ✅ 免登录 | ❌ 需 `a_bogus` 签名 | ❌ 需 Key |
| 弹幕（带时间戳） | ✅ 免登录 | ❌ 需签名 | ❌ 无此数据 |
| 评论 | ✅ 免登录 | ❌ 需签名 | ❌ 需 Key |
| 字幕 | ⚠️ 需登录态 | ❌ 需签名 | ⚠️ 正文可得（需 Key） |
| 官方分章 | ✅ 免登录 | ❌ 无 | ❌ 无 |
| 热搜 / 话题词 | ✅ 30 条 | ✅ 49 条 | ❌ 需 Key |
| 配图看图 | ✅ 封面 + 首帧 + 分章图 | ✅ 热点配图 | ⚠️ 需 Key |
| 单博主完整投稿 | ✅ 零配置 | ❌ 需签名 + Cookie | ❌ 需登录态 |
| 合集与系列 | ✅ 零配置 | ❌ | ❌ |
| 专栏 | ⚠️ 列表可，正文需登录 | ❌ | ❌ |
| 动态图文 | ❌ 需登录态 | ❌ | ❌ |
| 单条深度拆解 | ✅ 成立 | ⚠️ 需工具 | ⚠️ 需工具 |
| 选题预判 | ✅ 成立 | ✅ 更强 | ⚠️ 需 Key |

**分工**：B站是拆解引擎（答「为什么火」）兼作品全景库（答「他怎么做到」），抖音是选题雷达（答「什么值得扒」），小红书是需要 Key 的第三极。

B站之所以能当引擎，是因为它是三家里唯一免费给出**带秒级时间戳的弹幕**的平台。弹幕是唯一免费且自带时间标注的情绪数据，没有它，情绪曲线只能靠猜。

## 五、工作流

五个动作，顺序不能跳。每步的完成标志见 [`docs/02-执行流程.md`](docs/02-执行流程.md)。

1. **定位候选** —— 按互动效率排序（点赞率、收藏率、评论率），不按绝对播放量。绝对量会被大号碾平。
2. **取证据** —— 元数据、弹幕、评论、官方分章四路并行，再补封面与分章图看画面，必要时抽帧和转写。
3. **对齐时间轴** —— 把弹幕、分章、评论压到同一条线上，定位钩子生效点、弹幕爆发点、质疑起始点。
4. **归因输出** —— 按固定骨架写，每条结论标注来自哪个接口的哪个字段、哪个时间戳。
5. **标注置信度** —— 说明缺了哪些证据，以及因此不能得出什么结论。

第 3 步是拆解与复述的分界线。跳过它，后面的输出再漂亮也只是摘要。

## 六、输出与置信度

```
■ 钩子（前 3 秒）  画面 / 口播 / 屏幕文字 / 音频 / 生效时间点 / 留人机制
■ 结构骨架        时间区间 | 章节内容 | 画面策略 | 弹幕密度 | 观众情绪
■ 情绪曲线        时间点 | 情绪 | 强度 | 触发原因
■ 争议点          评论区高赞质疑 + 对应弹幕时间
■ 传播基因        梗 / 选题 / 形式 / 情绪
■ 可复用配方      公式 / 必须保留 / 必须避开 / 适用时长
■ 置信度          高·中·低 + 缺失的证据说明
```

| 可用证据 | 置信度 | 能得出 | 不能得出 |
|---|---|---|---|
| 弹幕 + 评论 + 分章 + 图 | 高 | 完整归因，结论可指回时间戳 | — |
| 弹幕 + 评论 + 图（无分章） | 中 | 结构靠弹幕时序反推 | 不得直接断言分章结构 |
| 仅评论 + 图 | 中 | 争议点、需求挖掘、视觉策略 | 禁止输出结构分析 |
| 仅元数据 + 标题 | 低 | 只能做选题定位 | 禁止称为拆解 |

三条硬规则：无时间信号时不输出结构分析；每条结论标注证据来源；拿不到就说拿不到，**不许用「可能 / 通常 / 一般来说」填空白**。

## 七、它不做什么

- **不绕过风控。** 小红书签名头、设备指纹属于风控体系，逆向它等于规避技术保护措施。抖音的 `a_bogus` 同理，走浏览器插件复用已登录会话，不走破解。
- **不采未授权个人数据。** 只碰公开发布的内容与其公开互动数据。
- **不当爬虫框架用。** 不建库、不建表、不做增量同步。证据包跟着作品走，一次一包。
- **不产出可照抄的文案。** 拆出来的是结构与配方，仿写要换题材、换表达、换素材。
- **不宣称全覆盖。** 三平台里只有 B站能做到零配置端到端，另外两家都要额外条件。
- **不把未测写成可用。** 没实测的链路一律标「未验证」，不写「支持」。

## 八、已知问题

**B站裸请求返回 `{"code":-352}`。** 必须带完整浏览器 UA 和 `Referer: https://www.bilibili.com/`。这解释了为什么 WebFetch 能通（自带浏览器头）而 curl 裸请求失败。

**弹幕和评论的 oid 类型不同。** 弹幕用 `cid`，评论用 `aid`。填反了静默返回空，不报错——这是最常见的失败原因。

**抖音的「假成功」。** `www.douyin.com/aweme/v1/web/hot/search/list/` 返回 HTTP 200 但 body 0 字节；App 端搜索 `status_code:0` 但 `aweme_list` 为 null。**200 不等于有数据。** 热点榜要用 `snssdk` 域。

**小红书的假 noteId。** `__INITIAL_STATE__` 里 22 个 24 位 hex ID 来自 `disableLikeNotes` 灰度名单，不是真实笔记。拿到 ID 必须先验证能否打开。

**小红书免登录不存在。** 详情页 302、搜索页 URL 带签名、`feeds:[]`。必须引入 API Key。

**热门榜的 stat 是入榜时刻的快照。** 做效率排序用快照没问题；做绝对量对比或趋势分析必须用 `view/detail` 取实时值。同一条视频一周内从 217 万涨到 1061 万。

**小红书 `note_url` 不能重建。** `xsec_token` 等 query 参数必须原样保留，用 `note_id` 拼接的链接读不到内容。

**判断成功的标准**：HTTP 200 + body 长度 > 0 + 目标字段非 null + 业务 `code` 为 0，四者同时满足。

完整清单见 [`docs/05-失败模式.md`](docs/05-失败模式.md)。

## 九、先做什么

**P0 · 修可验证的问题**：无时间信号时的降级输出、采集量与总量的口径分离、引文必须绑定时戳、无画面证据时的断言禁令。这些收益确定，不需要新工具。

**P1 · 用小样本选主路径**：6 类样本各 1 条，每条只看 60 至 120 秒，记录错误类型而不追求全片校订；同时给命中率类指标补上偶然基线。

**P2 · 按痛点扩展**：小红书 Key、多平台批量采集、系列索引自动化。这些是外围工程，不要让它们吃掉分析预算。

验收方法与交付格式见 [`docs/08-验收与交付.md`](docs/08-验收与交付.md)。

## 十、合规

采集优先级：官方开放平台 > 平台官方工具 > 第三方合规 API > 浏览器插件（低频人工触发）> 自建爬虫（仅公开页、严格限速、只读）> 协议逆向 / RPA（不做）。

采集频率遵守官方节奏（小红书官方 API 默认 QPS=1）。产出的是结构与方法，不是内容本身。
